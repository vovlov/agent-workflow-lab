# Agent Workflow Lab

Учебный пример к статье об ИИ-агентах, за действия которых можно отвечать.
Показывает границу между предложением planner и разрешённым действием.
Токены, ключи, аккаунты и реальные сообщения не нужны.

## Запуск

Python 3.10+. Основная версия использует только стандартную библиотеку.

```sh
python3 agent_lab.py
python3 -m unittest -v
```

Программа покажет синтетический предпросмотр, имитацию принятой доставки и
алгоритмический ответ. Никому ничего не отправляется.

Для варианта с LangGraph:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-graph.txt
.venv/bin/python langgraph_demo.py
.venv/bin/python -m unittest -v
```

После установки зависимостей оба сценария работают без сети. Проверено с Python
3.12 и LangGraph 1.2.20. Зафиксирована версия верхнеуровневого пакета; файл
requirements не является полным lockfile транзитивных зависимостей.

## Что изучать

- `agent_lab.py`: библиотечный API обращения, проверка владельца, версия и срок
  предпросмотра, атомарное подтверждение с outbox, состояния доставки и журнал.
- `discuss`: ограниченный agent loop с разрешённым чтением учебного FAQ.
  Программный planner заменяет модель для эксперимента. Предложение `send`
  не даёт прав на отправку, а режим без planner сохраняет базовый ответ.
- `langgraph_demo.py`: подготовка → `interrupt` для человека → доставка.
  Предпросмотр подготовлен отдельно от узла, который повторяется при resume.
- Тесты: чужое подтверждение, изменение снимка, срок, повторы, восстановление
  очереди, неопределённая доставка, конкурирующие захваты и предел шагов.

## Важная граница

`approve` — API библиотеки, а не HTTP-сервис с аутентификацией. Значение principal
должен устанавливать доверенный адаптер. Имя из текста сообщения не доказывает
личность. Состояние `accepted` означает приём транспортом, а не прочтение человеком.

При исключении отправителя результат становится `unknown`: внешняя сторона
могла уже принять сообщение. Автоповтора нет. Незавершённые `sending` разрешено
переводить в `unknown` только после подтверждённого завершения старого воркера.
Идемпотентность подтверждения в SQLite не равна exactly-once в сети.

## Чего здесь намеренно нет

HTTP/Telegram-адаптера, настоящего LLM-провайдера, шифрования, политики хранения,
денежного бюджета, мониторинга, резервирования, distributed leases и готового
публичного сервиса. Используйте только синтетические данные. Соединение SQLite
синхронное, отдельное для каждого вызывающего кода.

`InMemorySaver` не переживает перезапуск процесса. Сохраняемый outbox сам по себе
не делает весь граф долговечным. Текст ответа planner недоверенный: интерфейс
должен экранировать его. Живому модельному адаптеру нужны проверка схемы,
deadline и сохраняемый бюджет, а не только предел числа шагов.

## Задания

1. Поменять текст после просмотра и подтвердить старую версию.
2. Имитировать отправку, после которой теряется ответ транспорта.
3. Подключить свой planner, сохранив прежние полномочия executor.
4. Добавить долговечный checkpointer и проверить перезапуск.
5. Спроектировать аутентифицированный адаптер канала и проверить границу прав.
